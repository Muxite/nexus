## Open follow-ups for the next session

Run in order; each is "implement → long soak → measure". The user's intent: don't ship many small things mid-soak. Land one cycle, then soak 6-24h, then re-plan from the data.

### Cycle 5 — DKG path actually fires trades

The DKG decision path is wired (`app/stages/dkg_trade.py` subscribes to `TOPIC_MARKET_LINKS_UPDATED`) but has never fired a trade because `market_links.final_score >= 0.8` is rare under live conditions. Likely fixes:

- Lower the gate to `>= 0.75` and add a `min_links_per_event` cap.
- Or: rework the linker's `final_score` formula (chunk-2b notes #3-5 — directness/novelty/deadline_fit/resolution_fit weights are equal today).
- Confirm `dkg_trade_links` idempotency table works on a real fire (it's untested under live conditions).

### Cycle 6 — Reranker on matcher top-K

User's research roadmap (cycle 1 plan §"Out of scope") calls for a cross-encoder reranker on the cosine top-K. Now that v5/v6 labels show some `R` (retrieval mismatch) responses, we can measure whether a reranker reduces R%. Two options:

- Small cross-encoder (`ms-marco-MiniLM-L-12-v2`, 33M params, CPU-friendly).
- Cheap LLM rerank call (one extra round-trip per top-K set).

### Cycle 7 — `/scrape mode=article` for HTML body text

Today HTML ingestion captures only `(url, title)` from the link-set. Adding a second `/scrape mode=article` per new URL gets cleaned body text, which `match.py:_fetch_title` could concat into the embedding (same way summary is for RSS). Cost: doubles HTTP volume to scraper-v2. Worth it if cycle 5/6 still see a lot of NEUTRAL on HTML-source articles.

### Cycle 8 — Graph-driven invalidation ("Panic sell" override)

User's strategy #4 from the cycle 3 conversation. When a new event in the DKG contradicts an open position's thesis (via an `event_edges` "contradicts" edge that doesn't exist yet), force-close the position with reason `contradiction`. Requires:

- Eventize to emit `contradicts`/`escalates`/`resolves` edges (currently only `confirms`).
- Closer to subscribe to `event.updated` and check open trades against the new event.

### Cycle 9 — Missed-edge plot review + prompt iteration

The 1-in-4 missed-edge plot tool exists (`app/dashboard/plots/missed_edge.py`) but nobody's actually looked at the PNGs to find patterns. After the cycle-3 soak has produced 50+ trades, review the plots and identify systemic mis-timings (always too late? too early?). Use that to tune `take_profit_pct`, `stop_loss_pct`, `stagnation_minutes`, or the v6 confidence-digit mapping.

## What's broken / smelly / worth knowing

- **Cache hit rate stays 0%** even though the `prompt_sha` cache is operational. Likely by design (each (article, market) pair is unique → unique prompt → unique sha → no reuse) but worth confirming. If real, removing the cache infra would simplify ai.py.
- **3 stale open trades from cycle 2** were force-closed at entry_mid (PnL=0) before snapshotting cycle 3. The "manual" close_reason marks them.
- **Per-event-type TTL** (user's strategy #2) isn't implemented — TTL is the global `closer.timeout_hours=1.5h`. News-shock arbitrage on a Polymarket micro-market probably wants 30-min TTL; long-horizon election markets want 12h+.
- **HTML body extraction** deferred — articles from HTML path have title only (no summary). Match stage's title+summary embed degrades to title-only for these. Decisions on HTML-sourced articles may be slightly weaker.
- **DKG path firing has never been verified end-to-end** under live conditions. The scaffolding works (tests pass) but no real `market_links.final_score >= 0.8` event has triggered a DKG trade yet.
