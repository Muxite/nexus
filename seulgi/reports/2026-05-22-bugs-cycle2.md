# Cycle-2 bug audit — must-address-soon

This merges two independent passes:

- **Audit A** (code/state): static check against the working tree plus on-disk
  evidence (WAL size, container state, etc.).
- **Audit B** (planned-logic): walked the post-cycle-2 control flow for
  correctness bugs and silent traps.

Numbering below is a single re-prioritised list; original audit IDs are noted
in brackets so the diff conversation maps cleanly.

No code was changed by this audit. Findings are ordered by urgency, not by
file.

---

## Critical — block the next deploy

### 1. Budget poller can't auto-unpause on restart  [B1]
`seulgi/app/budget.py:85-119` initialises `paused_prev = None`. If the bot
restarts with `data/budget_paused.flag` on disk and the cap has recovered:

- First poll: `paused = False`, `paused_prev = None`
- `unlink` branch needs `paused_prev is True` → never fires
- Flag stays on disk forever; `process()` short-circuits every headline
  until someone manually deletes the file (or the cap dips below threshold
  again, which is rare after a top-up).

Directly contradicts the handoff's "next session" step #2 (*"budget tile
shows remaining > $5; `data/budget_paused.flag` is gone after ≤5 min"*).

**Fix:** initialise `paused_prev = flag.exists()` before the loop — or,
simpler, make the toggle idempotent: always `flag.write_text(...)` when
paused, always `flag.unlink(missing_ok=True)` when not paused. Log only on
edges; reconcile state every tick.

### 2. `news_memory` failure silently elevates everything to `BREAKING`  [B3]
`engine.py:302` initialises `freshness = FreshnessResult(label="BREAKING")`
then attempts `news_memory.assess`. On exception the bare `except` logs to
debug and leaves the default in place. `BREAKING` is the most permissive
label — it bypasses the REHASH / STALE_RETURN short-circuit. A broken
NewsMemory (chromadb segfault, slow disk, OOM) → every headline gets full
LLM cost **and** trades.

Given the chromadb HNSW corruption history (2026-05-21), this is a real
recurrence path.

**Fix:** fail closed. On `assess` error, set label to `STALE_RETURN` (or a
new `UNKNOWN` label included in `short_circuit_labels`) and bump a metric.
Add a startup check that `news_memory.size > 0`.

### 3. `budget_paused` short-circuit writes no funnel rows  [B2]
`engine.py:255-266` returns early with just a `logger.debug` call. Every
other short-circuit (`REHASH`, `low_similarity`, `ai_paused`) calls an
`evaluate_*_skips()` helper so the funnel still has one row per
(engine × match). Budget pause does not.

The `decision_funnel` will be silently missing every headline that landed
during pause — Phase 5 replay against `decision_inputs` will also be
sparse for the paused window.

**Fix:** add `evaluate_budget_paused_skips` (mirror of
`evaluate_ai_paused_skips`) or accept the gap explicitly and document it.
Either also gate this short-circuit **above** `freshness.assess` /
`bump_market_heat` / `insert_signal` so the no-cost story stays honest —
currently you still pay for those.

### 4. Phase-5 `decision_inputs` rolled back silently by gather timeout  [B4]
`engine.py:688-705` schedules `insert_decision_input` with
`asyncio.create_task` **after** `_batched_gather()` has started
(`engine.py:719`). The writer connection is serialised by aiosqlite's
worker thread, so:

- If the `create_task` lands while gather's `BEGIN ... COMMIT` is open,
  the insert is silently included in that transaction.
- If gather hits `wait_for TimeoutError` (line 720) → batch is rolled back
  → the `decision_input` row is rolled back too, silently.

The "fire-and-forget, never block the pipeline" intent is contradicted by
the silent rollback.

Compounding the issue: the task handle is never held — Python may also GC
the pending task. Same pattern in `ai.py:419` for `llm_parse_failures`.
[A2]

**Fix:** move the `insert_decision_input` call **before** `_batched_gather`
and `await` it inside its own tiny `async with db.batch():`. For
`llm_parse_failures`, hold task refs in a set with
`add_done_callback(s.discard)`. Acceptable cost: one extra commit per
headline.

### 5. WAL is 524 MB on a 7.1 GB DB → checkpointing is silently broken  [A1]
`PRAGMA wal_autocheckpoint=1000` (`db.py:545`) targets ~4 MB. A 524 MB WAL
means **something is holding a long-lived read txn open** — almost
certainly the dashboard subprocess or `impact_tracker` — and SQLite can't
truncate past the oldest reader.

Symptoms: degrading read latency, fatter recovery on crash, page cache
thrashing.

**Fix:** either (a) split readers onto their own short-lived connections
that close between polls, or (b) add a periodic
`PRAGMA wal_checkpoint(TRUNCATE)` task and confirm the held-back reader.

## High-impact — fix this week

### 6. Three early short-circuits fan out 20-way writes outside `db.batch()`  [B5]
- Freshness short-circuit (`engine.py:381-391`)
- Low-similarity short-circuit (`engine.py:436-445`)
- AI-paused short-circuit (`engine.py:540-548`)

Each is `asyncio.gather(*[engine.trader.evaluate_*_skips(...)...])` with
no outer `db.batch()`. At 20 engines × ~25 markets that's up to 500
autocommits per headline. The handoff already established that the same
fan-out with `db.batch()` is the right shape (`engine.py:644-657`).
REHASH is one of the most common short-circuits.

**Fix:** wrap each early-return gather in `async with self._db.batch():`.
Single fsync per short-circuit headline instead of hundreds.

### 7. `MIN_CONFIDENCE=0.15` × `mean_p` confidence is wide-open trading  [A4]
`seulgi/docker-compose.yml:35` drops the floor to 0.15 and `ai.py:751`
redefines `confidence` as `mean_p` (the winning-direction probability,
dragged down by non-voting samples).

Together with Stage-2 LLM removed and sim-floor at 0.50 only, the bot is
effectively in "trade on anything that vaguely matches a market" mode. The
change is explicitly tagged *"tighten after one day of post-fix operation"*
in the inline comment — **set a Telegram or calendar reminder so it
actually happens.** Currently this is the easiest channel for runaway burn
once the OpenRouter budget is topped up.

### 8. Behavior change in `trader.py`: relevance-skip rows no longer hit `trades`  [A5]
The pre-2026-05-22 contract was: one `trades` row per (engine × match) with
`skip_reason='not_relevant:*'`. The new code (`trader.py:407-440`) appends
to `decisions` for the `engine_results` bulk insert **but no longer calls
`_record`** → no row in `trades`.

Dashboards / analyses that historically counted skipped trades via
`trades.skip_reason LIKE 'not_relevant%'` will silently report fewer skips
post-fix. The comment claims `engine_results` covers it, but
`engine_results` rows don't carry the same per-match columns
(`mid_yes`/`mid_no`/`relevance_score` etc.). Verify nothing in
`dashboard.py` and `scout_funnel_core.py` depends on the old shape.

### 9. Engine-pause guard is permanently off, and the name lies  [A3 + B6]
`_refresh_engine_pause_cache` (`engine.py:188`) is now
`while True: sleep(3600)` but is still scheduled in `main.py:541-543` as
`engine-pause-refresh`. The `active_engines` filter at
`engine.py:583-585` is therefore dead code, and `_paused_engines` never
gets populated.

That removes the safety net that would shut off a chronically losing
engine. With 20 engines, `MIN_CONFIDENCE=0.15`, sim-floor 0.50 only, and
no Stage-2 LLM, a bad engine can drain its pot uninterrupted.

**Fix:** either
- (preferred) keep the plumbing but actually wire the refresher. Requires
  the `(engine_name, closed_at)` composite index on `trades` plus moving
  the rolling-hit-rate read to a separate RO clone connection.
- (cheap) delete the task + `_paused_engines` / `active_engines`
  plumbing entirely; rename the task to `engine-pause-refresh-DISABLED`
  and emit a startup `logger.warning` so the absence is loud.

### 10. 300 s gather timeout is overkill and holds backpressure  [A10 + B12]
The post-fix bump from 90 s → 300 s (`engine.py:719`) means a hung gather
can stall every subsequent headline for five real minutes (concurrent
`process()` calls serialise on `_batch_lock`).

With Layer-B / Layer-C now fixed, 300 s is overkill; revert to ~30-60 s.
Cheaper to lose one headline than to back up five minutes of incoming
traffic. Add a Telegram alert if `[runner] ENGINE GATHER TIMEOUT` ever
fires.

## Medium — code-health / token-cost / smaller correctness

### 11. `INSERT OR REPLACE INTO decision_inputs` overwrites  [B8]
`db.py:2470` — `signal_id` is the PK. If anything ever re-processes a
headline (retry path, replay-on-startup) the original row's `embedding`,
`matches_json`, `decided_at` get replaced. The replay harness assumes
append-only semantics.

**Fix:** `INSERT OR IGNORE` and log on conflict (`changes() == 0`).
Simpler and preserves Phase-5 immutability.

### 12. Per-engine scoped pre-AI rules run **after** the LLM call  [B9]
`_run_engine` (`engine.py:879-891`) applies `gate_pre_ai_scoped` to filter
the engine's survivors **after** `classify_batch` already ran across the
union of survivors. Any market that's culled by **any** engine's scoped
rule still incurred Stage-3 tokens.

**Fix:** in `process()`, after the universal gate, also compute the
intersection of survivors that pass at least one engine's scoped rules
→ pass that set to `classify_batch`. Per-engine filter still runs in
`_run_engine` for variant-specific culls. Net token cost drops without
changing semantics.

### 13. `llm_parse_failures` rows have `signal_id=None`  [B10]
`ai.py:413-425` writes parse failures with `signal_id=None`. The handoff
promises this drives the Phase 2.2 categorisation work. Without the
`signal_id` you can't join failures back to the headline / freshness label
/ source — you lose half the categorisation axes.

**Fix:** thread `signal_id` through `classify_batch` (kwarg from
`engine.py:551` onward) and persist it.

### 14. `RelevanceFilter` + `lessons` are dead but still constructed/threaded  [A7 + B7]
- `main.py:333-342` builds the `RelevanceFilter` object; `engine.py` only
  reads `_min_top_similarity` off it via `getattr`.
- `relevance.py` (309 lines) is now dead in production.
- `engine.py:228-239, 525` still calls `_get_lesson_notes_cached` and
  threads `lesson_notes` through to `classify_batch` where `ai.py:318`
  then sets `lessons_block = ""`.

**Fix:** collapse to a tiny `SimGate` dataclass holding one float
(`min_top_similarity`); drop `RelevanceFilter` from `main.py`. Keep
`relevance.py` in git history. Rip out the `lesson_notes` plumbing end
to end.

### 15. `_write_lock` is a no-op shim with eight live callsites  [A8]
`db.py:625` is just `yield`. The contract — "writes serialise on the
aiosqlite worker thread" — is unwritten and silently breaks the moment
anyone adds a second connection (e.g., a future readonly clone for #9).
At minimum add an assertion that `self._conn` is the only writer, or
rename the shim to make the no-op obvious.

### 16. `news_chroma.bad_20260521/` still on disk (275 MB)  [A9]
Marked "safe to delete after 2026-05-29". Today is 2026-05-22 — set a
`/schedule` to actually delete it on the date, or expect to find it in
a year. Also: no auto-rebuild guard exists for the next chromadb HNSW
corruption (plan item C.3, still pending).

### 17. Two fragile import idioms  [A6 + B15]
- `engine.py:262` — `import budget as _budget`
- `main.py:543` — `__import__("budget").poll_loop(...)`

The rest of the codebase uses module-level imports (`from relevance import
RelevanceVerdict`). These work today because `cycle.py` runs from inside
the app dir; they break any script that imports `engine` or `main`
differently (tests, ad-hoc CLI). `__import__` also makes static analysers
and grep miss the dependency. Switch to `from app import budget` if the
package layout supports it, or fix the package layout.

### 18. `_engine_should_pause` is `async` without an `await`  [B13]
`engine.py:165-181`. It's just a set-membership check now. Make it `def`
(cuts await overhead and signals intent).

### 19. `Engine.relevance_keep_scores` is dead  [B14]
Set in `build_engines`, never read. Remove the field.

### 20. `llm_calls` writer never wired  [B11]
Schema and writer exist; `ai.py` never calls `log_llm_call`. Until this
is wired, the "replay without paying tokens again" pitch isn't real —
`decision_inputs` alone reproduces inputs but not LLM responses.
Explicit handoff TODO (§4) — listed here so the lineup is complete.

## Recommended fix ordering

1. **#1** (budget poller startup) — single-line bug, traps the bot
   indefinitely after a top-up. Fix before the next OpenRouter top-up.
2. **#2** (news_memory fail-open to BREAKING) — silent cost / risk blow-up
   if chromadb misbehaves; precedent exists from 2026-05-21.
3. **#3** (budget short-circuit funnel gap) — data integrity for the
   Phase 5/6 replay program.
4. **#4** (decision_inputs ordering) — fixes the rollback-silently
   footgun; preserves the Phase-5 capture.
5. **#5** (WAL holdout reader) — investigate and unblock the truncate.
6. **#6** (wrap the three early-return gathers in `db.batch()`) — easy
   10× write-perf win on the most common path.
7. **#7** (revisit `MIN_CONFIDENCE=0.15`) — schedule explicitly; the
   inline comment promises it.
8. **#10** (drop gather timeout to 30-60 s) — backpressure hygiene.
9. **#12** (move pre-AI scoped gate before `classify_batch`) — token
   savings.
10. **#9, #11, #13, #14-19** — code-health pass; do together to cut a
    clean cleanup commit.

Items **#20** (`llm_calls` writer) is an explicit handoff TODO (§4) —
fold into the planned Phase 2.2 / replay work, not into this fix batch.
