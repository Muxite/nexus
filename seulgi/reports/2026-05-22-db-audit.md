## 4. Writer methods + `_write_lock`

`_write_lock` is a no-op `@asynccontextmanager` (db.py L589-615) that just
`yield`s. The docstring documents the cycle-2 finding: production
deadlock when it actually serialised. **Confirmed dead-code shim** — keeps
the diff small and prevents callers from removing `async with self._write_lock():`
boilerplate. Recommendation: leave it as-is during forensics; remove in
Phase-1 db.py refactor when call sites can change.

`savepoint()` (db.py L622-661) has **zero callers** in `app/` (grep
across `app/*.py` returns only its own definition). The docstring claims
"Phase 1 R2: trader.evaluate wraps `insert_trade + open_position` in
this" — that wrapping is not present in `trader.py` today. Dead code,
but harmless. Recommendation: keep for Phase 1 rewrite (trader.py
rewrite is the explicit place to wire it back).

## 6. Skip-row contract — 6.6M rows in `trades`

Live numbers (`SELECT COUNT(*) FROM trades WHERE skip_reason IS NOT NULL`):

```
trades.skip_reason NOT NULL : 6,611,748
trades.skip_reason NULL     :       498  (= executed)
engine_results.executed=0   : 3,395,107  (= skips, correct location)
engine_results.executed=1   :       498
```

Skips are written to BOTH tables (trader writes per-market skip rows to
`trades`; `record_engine_decisions` writes the per-engine summary to
`engine_results`). Cycle-2 contract: only `engine_results` carries skips;
`trades` is for executed attempts + closures. The 6.6M skip-row tail
bloats every `get_decision_funnel` and PnL scan, and partly wastes
`(engine_name, decided_at)`.

Recommendations (matches master plan Bug 8 + A1.4):

- **(a) Backfill / archive move:** export skip rows to
  `data/archive/trades_skip_rows.sqlite` then
  `DELETE FROM trades WHERE skip_reason IS NOT NULL`. Run inside a
  single transaction with `PRAGMA temp_store=MEMORY`; expect ~30 min
  on 6.6M rows. Compact via `VACUUM` afterward (frees ~4-5 GB).
- **(b) Hard-stop new skip writes:** modify the trader to call
  `record_engine_decisions` only and skip `insert_trade(... skip_reason=…)`.
  Phase 1 trader.evaluate rewrite is the right scope (already planned).
- **(c) Leave-for-archive is technically safe** — funnel queries still
  work — but the cost (full scans, doubled storage) compounds daily.
  Don't leave.

Recommended order: ship (b) first to stop the bleed, then (a) once
trader rewrite is stable.

## 9. Cycle-2 fixes vs code drift (CRITICAL)

Handoff `2026-05-22-v2.md` §1 and §6 document three load-bearing
fixes shipped in cycle 2. The audit cross-checks code as of
2026-05-22 18:00 UTC and finds:

| Cycle-2 documented fix | Status in code |
|---|---|
| `isolation_level=None` on `aiosqlite.connect(self._path)` (Layer C) | **NOT APPLIED**. db.py:469 still calls `await aiosqlite.connect(self._path)` with default isolation. No `isolation_level=None` kwarg. |
| `batch()` ROLLBACK-on-entry (Layer B) | **NOT APPLIED**. db.py:552 enters with bare `await self._conn.execute("BEGIN")`. No probe ROLLBACK first. |
| `batch()` shielded rollback (`asyncio.shield(...)` around cleanup) | **NOT APPLIED**. db.py:571 does plain `await self._conn.rollback()` inside the except branch. `asyncio.shield` is not imported/used anywhere in db.py. |
| Outer `db.batch()` removed from `_batched_gather` (Layer D) | (engine.py audit scope — sibling A0.5) |

The `batch()` `_batch_lock` serialisation IS implemented (good). Per-row
inserts under default isolation are fine today **only because the bot is
budget-paused** (1 open position, low concurrency). When LLM volume
returns and a `batch()` caller is cancelled at an await, the original
Layer B failure mode can re-occur.

**Recommendation:** re-apply the three fixes in a surgical patch before
Phase 1 begins:

```python
self._conn = await aiosqlite.connect(self._path, isolation_level=None)
# batch():
try:
    await self._conn.execute("ROLLBACK")   # recover stale state
except Exception:
    pass
await self._conn.execute("BEGIN")
…
# except branch:
try:
    await asyncio.shield(self._conn.rollback())
except …
```

This is high-value, low-risk, and is the entire reason A0.6
exists — these fixes are tribal-knowledge that exists in prose
but not in the code shipped to the container.
