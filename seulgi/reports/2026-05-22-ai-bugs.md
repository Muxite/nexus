## 1. Prompt structure — what the model actually sees

`_BATCH_PROMPT_TEMPLATE` (ai.py:85–111) renders the following user
content (one call per ensemble sample, N=3):

```
Headline: {headline}
{source_block}{lessons_block}{republish_block}{mkt_ctx_block}
Evaluate the headline against each of the following Polymarket questions:

{questions_block}

For each question output exactly:
{"idx": <0-based index>, "p_yes": <0.0-1.0>, "p_no": <0.0-1.0>,
 "p_neutral": <0.0-1.0>, "p_alpha": <0.0-1.0>, "risk": <0.0-1.0>,
 "reason": "<one sentence>"}

Rules:
- p_yes / p_no / p_neutral …  MUST sum to 1.0 …
- If current mid price ≥0.85 or ≤0.15 → shift mass to p_neutral
- Trust: state-media / partisan / tabloid → shift mass to p_neutral
- p_alpha = probability the argmax-direction trade is +EV in 5–30 min …
- risk    = expected magnitude of 5-minute |Δprice| on 0–1 scale …
- Respond with EXACTLY this JSON shape: {"results": [<array of {n} objects>]}
```

Per-market line (ai.py:332): `N. [YES mid={mid_yes} | sim={similarity:.2f}
{relevance?}] {question}`. Optional blocks:

* `source_block` — `"Source: {host}\n"` when known.
* `lessons_block` — **always empty** since 2026-05-22 (placeholder
  retained so `.format()` doesn't crash; ai.py:308–313).
* `republish_block` vs `freshness_block` — exclusive; freshness wins
  when a FreshnessResult was supplied. Freshness block emits label,
  nearest age, cosine_dist, and up to 3 prior similar headlines.
* `mkt_ctx_block` — 30-min vol/mean/min/max/cur/drift per market.

System msg `_BATCH_SYSTEM_MESSAGE` primes "output ONLY a JSON array".
`response_format={"type":"json_object"}` enforced (ai.py:386).

**No `<scratch>` / chain-of-thought block today** — model emits JSON
directly. Master plan A4E.4(d) wants to add one.

## 3. Parse-failure modes

**Schema gap on the live DB**: `llm_parse_failures`, `llm_calls`,
`decision_inputs` are referenced in code/docs but absent from the
live DB (only the 15 legacy tables). The snapshot
`pre_stop_20260522T180029Z` has all three — the migration ran once,
DB was reset, migration hasn't replayed. The CREATE TABLE is also
missing from `app/db.py`. The writer referenced in handoff §2 was
never committed to schema. Analysis below uses the snapshot's 67
rows (full table).

### 3.1 Every failure is `max_tokens` truncation on `gemini-2.5-flash`

```
model                       n_rows
google/gemini-2.5-flash         67
google/gemini-2.5-flash-lite     0
error_msg                   n_rows
"batch parse returned None"     67
stage                       n_rows
"prediction"                    67
```

All 67 failures are the premium model.  Raw response length:
`min=1, median=46, mean=115, max=3574` chars.  Truncation tells:

| ends_with | n |
|---|---:|
| `{` only | 17 |
| ends mid-key with `:` | 16 |
| mid-`p_yes:` or `p_no:` value | 24 |
| `[` | 1 |
| valid-looking close `}` | 1 |
| stray double-period `."."` mid-`reason` | 1 |

Interpretation:

* `max_tokens = 160·n + 100` is too tight for `gemini-2.5-flash`. At
  n=1 (12 rows) the cap = 260 tokens — observed truncation at ~50
  chars implies the model is emitting reasoning preamble that
  flash-lite doesn't. Suggest `≥ 400 + 200·n`.
* Truncated batches drop the *entire* batch to per-market
  `classify()` (ai.py:430), which uses the **non-premium** model and a
  different prompt (`_PROMPT_TEMPLATE`). Premium-routed batches
  silently downgrade — no telemetry today.
* Not observed: smart-quote/unicode issues, schema drift, prose
  preamble (`response_format=json_object` is doing its job).
* One row had stray `."."` mid-`reason` — a regex-fallback (master
  plan A4E.4(b)) would have recovered ~11 well-formed preceding
  objects.

### 3.2 Writer is *not actually wired*

No `log_parse_failure` method in `app/db.py`; no call site in
`app/ai.py`. The 67 snapshot rows came from a path since removed.
The "fire-and-forget write" in the spec is aspirational — Phase-5
replay tooling will be blind once the migration is re-run.

## 4. `confidence` semantics — confirming A0.3 from the AI side

A0.3 (trader-entry-bugs.md §1–§2) flagged `result.confidence` as
ambiguous from the consumer side. Confirming the producer:

`_aggregate_ensemble` (ai.py:646–742) — the *exact* lines:

```python
# ai.py:713–719
if direction == Direction.YES:
    mean_p = p_yes
elif direction == Direction.NO:
    mean_p = p_no
else:
    mean_p = p_neu
confidence = p_alpha if p_alpha > 0.0 else mean_p
```

Three findings:

1. **Docstring lies.** `_aggregate_ensemble`'s docstring
   (ai.py:651–668) advertises `confidence = mean_p_winner ×
   agreement`. The code drops `× agreement` and conditionally
   substitutes `p_alpha`. Out of sync since cycle 7.
2. **`p_alpha == 0.0` is supposed to mean "do not bet"**, but the
   fallback `confidence = p_alpha if p_alpha > 0 else mean_p_winner`
   rewrites that explicit zero to the directional mean — exactly the
   rows you want to reject get promoted.
3. **No agreement penalty** in the producer. Trader's
   `min_agreement: 0.66` runs separately and fails open at
   `agreement=0` (A0.3 §7). 1/1/1 tie → NEUTRAL (caught later);
   2/3 split → confidence reported as if unanimous.

### Recommendation for Phase 1

Stop overloading `confidence`. Emit three distinct, unconditional
fields and let the trader calibrator combine them:

```
confidence_raw = mean_p_winner          # model's stated p(direction)
p_alpha        = mean(sample.p_alpha)    # model's stated +EV prob
agreement      = max_votes / N           # 0..1
```

Retire the `2·conf − 1` edge rescale (A0.3 §1 already labelled it
not-an-EV). All three fields are already persisted on the trade row.

## 5. NEUTRAL bias — verifying cycle-2 fixes

24-h sample, `engine_results.decided_at > now('-24 hours')` on the
live DB:

| Bucket | rows | % |
|---|---:|---:|
| `not_relevant:*` (Stage-2 sim-gate) | 249,539 | 55.9% |
| `RULE_*_SKIP` (pre-AI rules) | 193,838 | 43.4% |
| Reached AI (post sim+rules) | 196,609 | 100% of "AI rows" |
| └ AI direction = NEUTRAL | 196,559 | 99.97% |
| └ AI direction = YES | 34 | 0.02% |
| └ AI direction = NO | 16 | 0.01% |

Per-headline view (n=983 headlines whose engine_results actually ran
through Stage-3 today): **975 (99.2%) had every market come back
NEUTRAL**; only 8 had ≥1 directional emit. Trades executed today: **2**.

Cycle-2's lessons-removal did NOT cure the NEUTRAL regression — the
100%-NEUTRAL pattern flagged on 2026-05-21 is still operating with
the new flash-lite default. Likely contributors:

1. The prompt nudges toward NEUTRAL on three axes (mid extremes,
   low-trust source, genuine uncertainty). The "Trust" rule names
   low-trust outlets only — no counter-rule for high-trust sources →
   one-sided regularisation.
2. Truncated premium batches (§3.1) fall back to the cheaper,
   single-market prompt which is *also* NEUTRAL-biased on rail mids.
3. No few-shot exemplars — model has no anchor for "what does
   p_yes=0.7 look like?".
4. Argmax ties resolve to NEUTRAL (ai.py:597), so (0.4, 0.4, 0.2)
   is mislabelled even though directional mass is 0.8.

Quick wins (before A4E.4 lands): balance the trust rule, bump
`max_tokens`, switch argmax tie-break from NEUTRAL to highest
directional bucket.

* `data/budget_paused.flag` is read in `engine.process()` and written
  only by `app/budget.py`. `ai.py` has no reference. Separation
  confirmed clean.
* OpenRouter **402** is **not** specially handled. `_call_api`
  (ai.py:506–538) retries 429 only; any other non-200 is logged at
  WARNING and returns None. The whole batch then falls through to
  per-market retries against the same cap, burning more 402s.
  Master plan B.9 minimum lift: detect 402 → ERROR log + sentinel
  the engine uses to set the budget flag immediately, instead of
  waiting on the 5-min poll.

1. **NEUTRAL emission rate ≈99.97 %** of post-relevance rows in the
   last 24 h. Prompt one-sidedly nudges toward NEUTRAL on three
   axes; argmax ties resolve to NEUTRAL; cycle-2 lessons removal

2. **`confidence` semantics are ambiguous** (`p_alpha` when emitted,

   responses 100 % of the time in the failure sample. Truncated
   batches downgrade to the non-premium per-market fallback path —
   silent, no telemetry.

   `app/db.py` schema, no writer in `ai.py`, live DB has no table.
   Phase-5 replay is blind without it.
