## System overview (quick orientation)

SEULGI is a polymarket trading agent in `seulgi/` running under
docker-compose:

```
┌─────────────┐       ┌──────────────┐     ┌──────────────┐
│  watchers   │──hl──▶│  EngineRunner│────▶│    engines   │
│ (RSS, etc.) │       │  (engine.py) │     │  (15 of them)│

                              │                    │
                              ▼                    ▼
                      ┌──────────────┐     ┌──────────────┐
                      │  ChromaDB    │     │  PaperTrader │
                      │ (news_memory)│     │  (trader.py) │
                      └──────────────┘     └──────────────┘
                              │                    │
                              └────────┬───────────┘
                                       ▼
                              ┌──────────────┐
                              │ aiosqlite    │
                              │ seulgi.db    │
                              └──────────────┘
```

- One watcher per source (RSS + HTML scrapers via `nexus-ujin`).
- Pipeline per headline: freshness label → pre-AI rule gate →
  low-similarity gate → relevance LLM (Stage 2) → AI classify
  (Stage 3) → per-engine `_run_engine` → `trader.evaluate` →
  decisions written to `trades`.
- 15 engines: 10 balanced variants, 4 inverted_highconf, 1 scout.
- Cycle is a boundary marker; positions and balances reset per cycle.
- Dashboard renders `data/dashboard/*.txt` every 30 s from in-memory
  state + on-demand DB queries.

## Strategic Decision Needed

The current architecture has accumulated layered restrictions
calibrated against the broken-MTM accounting era. After 8 days of
incremental fixing we've hit a wall: the system is structurally
fragile and stops trading at every cycle reset.

**Two paths forward:**

### Path A — Continue incremental fixes
Bisect the B-WRITES regression by reverting one change at a time
on a fresh DB until writes flow. Then patch the responsible code.
Roughly 1–3 sessions of careful work. Risk: even if fixed, the
larger system stays complex and fragile.

### Path B — Partial revert to "honest infinite trade" + curated re-add
Roll back the over-restrictive filtering layer (Phase E.1 rules,
M4 variant filters, Kelly sizing, lessons, hour pause) to get back
to a simpler, higher-volume baseline. Keep the honest-accounting
plumbing (MTM, fees, slippage, share quantization). Then layer
filters back **from evidence only** as honest data accumulates.

Roughly 1 session of work + 7 days of soak. Lower long-term
maintenance burden. Honest baseline ROI is the goal.

**Recommendation: Path B.**

Justification: the current system has not produced verifiable
profit under honest accounting. The infinite-trade era's volume
was real but its profit display was a bug. Going back to a simple
honest baseline lets us measure whether ANY strategy works before
layering complexity. See "Path B execution plan" below.

## Known bugs

### B-WRITES — the recurring writer freeze (UNRESOLVED)

**Symptom**: After a cycle reset, `trades` and `engine_results`
tables stop receiving inserts. `signals` and `usage_events` keep
flowing.

**What we know**:
- Persists across rebuilds and config reverts.
- No tracebacks, no `engine 'X' error` warnings, no asyncio task
  exceptions visible.
- Dashboard `[dash] variant_stats query failed:` warnings appear
  every ~45 s — the heavy GROUP BY queries time out at 10 s.
- External read tests of the same queries return in <1 s.
- AI calls are intermittent: sometimes fire ("ensemble classify"
  logs), sometimes silent for minutes.
- WAL file (`seulgi.db-wal`) grows to 400+ MB and doesn't
  checkpoint efficiently.

**Best guesses**:
1. **Dashboard writer starvation**: 5 heavy queries running every
   30 s × 10 s each blocks aiosqlite's single writer thread.
2. **`_engine_should_pause` per-engine queries** under contention
   serialize at 10 s each (15 engines × N headlines).
3. **The cycle-reset race**: stopping the writer mid-flight while
   resetting cycle state leaves something in a stuck state.

**Reproduction**: run `reset_cycle.py` while the writer is busy,
then recreate the container. Within a minute writes freeze.

### Dashboard query timeouts (LIKELY CAUSE OF B-WRITES)

`dashboard.py::_write_main` does 5 heavy queries per 30-s tick:
`variant_stats`, `decision_funnel`, `confidence_buckets`,
`freshness_counts`, `freshness_buckets`. Each has a 10 s `wait_for`.
All 5 join/group across the multi-million-row trades table.

When the writer is busy, these queries pile up and block the
writer further. The mitigation (cycle-scope + 1h window) helps
when there's data; right after a reset with 0 rows, the queries
SHOULD be instant. They aren't. Suspect lock contention with
aiosqlite's single connection.

### `scout`'s `engines_exclude` annotations are INERT

The 7 rule files have `engines_exclude: scout` in their
frontmatter, and `rules.py::gate_pre_ai` was updated to accept an
`engine_root` arg. But the runner's call site does NOT pass
`engine_root` — the per-engine pre-AI gate refactor that would
wire this was reverted because it triggered B-WRITES.

To activate scout's bypass, the runner needs per-engine pre-AI
gating, which is a tricky refactor (see Path B execution plan).

### Phantom-PnL bug (HISTORICAL, fixed)

Pre-`027450f` the dashboard reported cumulative `total_staked` as
"realized PnL," giving a `+$236` reading when actual was `$0`.
This is what made the infinite-balance era look profitable.
**Fixed**, but a recurring reminder that visible numbers must be
audited.

## Path B execution plan (the recommended next move)

### Phase 1 — Stabilize writes (must do first)

1. **Snapshot current DB** to a dated dir.
2. **Reset cycle** (cycle 5).
3. **Bisect B-WRITES**: in a known-good baseline (before today's
   perf work), confirm writes flow. Then add ONE change at a time
   until writes stop. The culprit is likely one of:
   - WAL mode interaction with the busy_timeout queueing
   - Dashboard heavy queries blocking writes
   - Cycle reset leaving connection in an odd state
4. **Cache the dashboard's heavy queries**. Move them to a 5-min
   background task that updates an in-memory dict. `_write_main`
   reads from the dict. This should permanently end writer
   starvation.

### Phase 2 — Simplify (the "revert" part of Path B)

Targets to remove or disable, with rationale:

| Item | Why drop |
|---|---|
| 7 pre-AI rules (`skip_*.md`) | Kill 84% of decisions, calibrated on broken-MTM data |
| Lessons table + injection in `ai.py` | Was poisoning LLM toward NEUTRAL, env-gate is a half-measure |
| Kelly sizing (`simulate_sizing.method`) | Skips small-edge signals; use fixed `max_position_usdc` |
| M4 variant filters (`direction_filter`, `freshness_filter`, `mid_yes_min/max`) | Surgical cuts on tiny samples — no evidence under honest accounting |
| Cluster-size sizing (1/√N) | Calibrated against broken-MTM data |
| Phase E.11 hour-of-day pause | Same provenance |
| 10 of 14 variants | Cull to 3-5 (one parent each: balanced, inverted_highconf, scout) |

Keep these honest-accounting wins:
- MTM accounting (`027450f`)
- Polymarket fee model (`c42f94e`)
- Slippage + share quantization
- Per-engine pot isolation
- WAL + indexes (today's perf work, once B-WRITES is fixed)
- `seulgi-test` profile + metrics module (today)

### Phase 3 — Set "honest infinite trade" baseline

- `infinite_balance: true` in `config.yaml` so capital isn't a
  constraint and AI runs on every headline.
- 3-5 variants only.
- All gates loose: `min_confidence` 0.40 → 0.30, `min_edge` 0.03 →
  0.005, `min_top_similarity` 0.30, no freshness short-circuit.
- Honest fee + slippage stays so PnL reflects reality.

### Phase 4 — Soak 7 days

Just let it run. Measure honest ROI on 1000+ executed trades.
Capture per-cell hit-rate + ROI in scout-style decomposition.

### Phase 5 — Layer filters back from evidence

Only re-add a rule when scout/baseline data shows the cell ROI is
significantly negative with n ≥ 200. Each addition is one PR with
the evidence table in the commit message. No more "intuition from
a tiny sample" gates.

## Verification after any change

1. Container starts cleanly: `docker logs --since 2m | grep simulate mode`.
2. `signals` advancing: max id > last known.
3. `trades` advancing: max decided_at within 60 s.
4. `engine_results` advancing.
5. Dashboard mtime < 90 s.
6. No `[dash] X query failed` spam (a couple at startup is OK).
7. No `Traceback` / `Task exception was never retrieved` in logs.
8. Tests still pass: `docker compose run --rm seulgi-test`.

If 3 or 4 fails: B-WRITES. Bisect.
