## The three plot-twists of today (full story)

### Plot 1 — SIGSEGV restart loop after the model revert

After yesterday's `gemini-3.1-flash-lite-preview` → `gemini-2.5-flash`
revert (commit `e5773da`), `docker compose restart seulgi` triggered
a 60-70s loop on `exitCode=139`. No Python traceback in the logs —
the bot was crashing in C extensions. 5+ restart cycles before I
noticed; container appeared "running" because the auto-restart kept
recovering.

**Diagnosis path:**
1. `faulthandler.enable()` added at the top of `main.py`. Rebuilt,
   restarted, waited for the next crash. C-level traceback caught
   the offender.
2. **First crash:** matplotlib `backend_agg.draw_path` running
   inside `concurrent.futures.thread` from `plotter._plot_latency_hist`.
   matplotlib's Agg backend is NOT thread-safe in the default
   ThreadPoolExecutor on first-render font_manager init.
3. **Mitigation:** added `SEULGI_DISABLE_PLOTTER=1` env-var default
   in docker-compose. Plotter is dispensable for trading; proper fix
   (dedicated executor or subprocess) is plan category B.5.
4. **Second crash** (after plotter disabled): chromadb
   `local_hnsw.py:94 in start()` from `news_memory.assess`. Root cause
   was a corrupted on-disk HNSW index — likely from earlier in the day
   when two seulgi containers (the standalone `seulgi` and the root-
   compose `jennie-seulgi`) were briefly both running concurrently and
   both writing to the same `data/news_chroma/` volume.
5. **Mitigation:** moved the corrupted dir aside
   (`data/news_chroma.bad_20260521`); the bot rebuilt the index empty
   on next boot. Lost ~25 days of news-dedup history; bot rebuilds
   from current traffic.
6. **Container has been stable ever since** (since 2026-05-21
   ~22:53 UTC; restart count 0).

Lessons logged in memory `project-dual-container.md` (always
`docker ps -a --filter name=seulgi` before debugging "why isn't the
bot doing X") and in the plotter docstring (KNOWN BUG block + the
two proper fix options).

### Plot 3 — engine fan-out writes are still silent (the actual blocker)

This is the bad news. The bot has been running with the new image
since 07:14 UTC. As of 07:55 UTC (~41 min):

- 582 signals written ✓
- 1,073 usage_events written ✓ (relevance + prediction LLM calls)
- 17 `ensemble classify` calls in the last 5 min ✓
- 0 trades written ✗
- 0 engine_results written ✗
- `insert_trade` and `record_engine_decisions` counters totally
  absent from `db_health.txt`

So the bot processes headlines, runs Stage-2 relevance LLM, runs
Stage-3 prediction LLM, then `_batched_gather` → `_run_engine` →
`trader.evaluate` → `_record/insert_trade` produces nothing. Same
symptom as yesterday's "engine fan-out hang"; super_scout doesn't
help when the write chain past Stage-3 is broken.

**Hypothesis (not yet confirmed):** `db.record_engine_decisions`
has `if not decisions: return` at db.py:1469 — if `trader.evaluate`
returns an empty list for all 20 engines, no `engine_results` row
ever lands. But `trader.evaluate` only returns `[]` if
`pre_ai_skips=[]` AND `relevance_skips=[]` AND `survivors=[]`.
With relevance filtering nearly everything as NO (today's pattern),
`relevance_skips` should be non-empty and trader.evaluate should
iterate it and call `_record` for each. Yet `insert_trade` counter
is absent.

**The next-session unblock** (plan's "Next 7 days" priority #1):
instrument `_batched_gather` in `seulgi/app/engine.py:638-655` with
three explicit log lines:

```python
logger.warning("[runner] [hid=%s] gather START n_engines=%d active=%s",
               hid, len(active_engines), [e.name for e in active_engines])
results = await _batched_gather()
logger.warning("[runner] [hid=%s] gather END n_results=%d n_exc=%d",
               hid, len(results),
               sum(1 for r in results if isinstance(r, BaseException)))
for engine, engine_results in zip(active_engines, results):
    n = len(engine_results) if not isinstance(engine_results, BaseException) else -1
    logger.warning("[runner] [hid=%s] engine %s decisions=%d", hid, engine.name, n)
```

Plus a log line BEFORE the `if not decisions: return` early-out in
`db.py:1469`. One headline through the pipeline + the log will reveal
whether `_run_engine` runs, whether `trader.evaluate` returns empty,
or whether the gather itself is hanging silently within the 90s
timeout.
